# مَقْلَمَة — منصة تعليمية (Supabase Edition)

منصة تعليمية كاملة بالعربية مبنية على HTML/CSS/JS فقط، تستخدم **Supabase** كباك-إند حقيقي (Auth + Database + Storage + Realtime).

---

## ✨ المميزات

- ✅ **مصادقة حقيقية** عبر Supabase Auth (تشفير كلمات المرور تلقائياً + JWT)
- ✅ **قاعدة بيانات Postgres** مع Row Level Security
- ✅ **Realtime** لكل من: الرسائل، الإشعارات، الكورسات، البث المباشر، حالة الاتصال
- ✅ **Storage** لرفع الفيديوهات (حتى 500MB)، PDF، الصور، والملفات
- ✅ **شات** مع مرفقات (صور/فيديو/ملفات) + حالة أونلاين/أوفلاين + حذف من الأدمن
- ✅ **بث مباشر** عبر HLS / YouTube / iframe (الأدمن يبدأ — الطلاب يشاهدوا فوراً)
- ✅ **مسارات تعليمية** + تحكّم الأدمن في وصول كل طالب
- ✅ **شريط تقدّم للرفع** + روابط مباشرة من Storage
- ✅ نفس التصميم الأصلي بدون تغيير في الـ UI

---

## 🚀 خطوات التشغيل (5 دقائق)

### 1) أنشئ مشروع Supabase
- ادخل على https://supabase.com/dashboard وأنشئ مشروعاً جديداً (مجاناً).

### 2) نفّذ ملف SQL
- من Supabase Dashboard افتح **SQL Editor** → **New query**.
- انسخ كامل محتوى `supabase.sql` والصقه، ثم اضغط **Run**.
- يُنشئ تلقائياً: كل الجداول + RLS + الـ bucket باسم `maqlama` + سياسات Storage + Realtime + Trigger إنشاء البروفايل تلقائياً.

### 3) عدّل `env.js`
افتح ملف `env.js` وضع:
```js
SUPABASE_URL: 'https://YOUR-PROJECT.supabase.co',
SUPABASE_KEY: 'YOUR-PUBLISHABLE-OR-ANON-KEY',
```
تجدهم في: Supabase Dashboard → **Project Settings → API**.

> **publishable / anon key** فقط — لا تضع `service_role` أبداً في الواجهة.

### 4) فعّل Email Auth بدون تأكيد إيميل (اختياري للتطوير)
حتى يعمل تسجيل الدخول فوراً بدون فتح إيميل:
- Supabase Dashboard → **Authentication → Providers → Email**
- عطّل **Confirm email** (Off) ثم Save.

### 5) شغّل المنصة
افتح `index.html` مباشرة في المتصفح، أو شغّل سيرفر بسيط:
```bash
npx serve .
# أو
python3 -m http.server 8080
```

⚠️ لا يوجد حساب أدمن افتراضي، ولا يُنشَأ أي حساب تلقائياً من المتصفح (هذا مقصود
لأمان الصلاحيات — كل صلاحيات الأدمن تُمنح فقط من داخل Supabase نفسه، وليس من
كود الواجهة). لإنشاء أول حساب أدمن، اتبع الخطوات في `SUPABASE_SETUP.md`
(إنشاء المستخدم من Authentication → Users بكلمة مرور قوية خاصة بك، ثم ترقيته
إلى `admin` عبر SQL Editor).

## 👥 إدارة الطلاب

من حساب الأدمن:
1. ادخل صفحة **الطلاب** → **إضافة طالب**.
2. لكل طالب: زرّ 🔑 (المفتاح) يفتح إدارة الوصول → اختر الكورسات / المسارات المتاحة له.
3. الطالب يرى فقط ما اخترته له (مفروض عبر RLS + UI).

---

## 📺 البث المباشر (لكل كورس على حِدة)

من صفحة **البث المباشر**، الأدمن يضغط **بدء بث جديد** ويختار:
- **الكورس** المرتبط بهذا البث (إجباري — كل بث مرتبط بكورس واحد فقط).
- **HLS (m3u8):** رابط `.m3u8` (من OBS + خادم HLS مجاني مثل Cloudflare Stream/Mux/restream).
- **YouTube:** رابط الفيديو المباشر.
- **iframe:** أي رابط بث آخر.

فقط الطلاب المسجَّلون في ذلك الكورس (مباشرة أو عبر مساره) يحصلون على إشعار فوري ويقدرون يشاهدوا هذا البث من صفحة البث المباشر. يمكن تشغيل عدة بثوث لعدة كورسات في نفس الوقت — كل طالب يرى فقط بثوث كورساته. هذا مطبَّق من قاعدة البيانات (RLS) وليس مجرد إخفاء في الواجهة.

> ملاحظة: WebRTC P2P حقيقي يحتاج خادم signaling/TURN — استُخدم HLS/YouTube لأنه مجاني وثابت ويعمل لأعداد كبيرة.

## 🗂️ الأقسام (تصفّح عام بدون تسجيل دخول)

أي زائر يفتح المنصة، حتى بدون تسجيل دخول، يقدر يضغط على قائمة الـ ☰ في صفحة تسجيل الدخول ثم **"الأقسام"** ليتصفّح كل الكورسات والمسارات المتاحة — الاسم والصورة والوصف فقط. لا يظهر له أي محتوى فعلي (فيديوهات/ملفات/اختبارات)، ومحاولة فتح أي كورس أو مسار تعرض له نافذة **"اشترك الآن"** مباشرة.

## 🔔 اشترك الآن

أي زائر غير مسجَّل، أو طالب مسجَّل لكنه غير مضاف لكورس/مسار معيّن، يرى عند محاولة فتحه نافذة **"اشترك الآن"** فيها:
- رابط واتساب مباشر.
- رابط صفحة فيسبوك.

لتعديل رقم الواتساب أو رابط الفيسبوك، افتح `script.js` وابحث عن `SUBSCRIBE_CONTACT` بالقرب من بداية الملف.

---

## 📁 رفع الملفات

يوجد الآن **bucket-ان** منفصلان:

- `maqlama` (عام): صور الأغلفة، صور المدرّسين، مرفقات الشات. تُرفع في مسارات مثل `courses/<uid>/...`، `paths/<uid>/...`، `chat/<uid>/...`.
- `maqlama-lessons` (**خاص/محمي**): محتوى المحاضرات الفعلي (فيديوهات، ريكوردات، ملفات PDF/صور المحاضرات) في مسارات `lessons/<courseId>/...`. القراءة منه تمر عبر فحص صلاحية حقيقي في القاعدة (تسجيل الطالب في الكورس أو في مساره، أو أدمن)، والرابط الذي يستخدمه المتصفح رابط **موقّع (signed) مؤقت** صالح لساعة واحدة فقط — وليس رابطاً عاماً ثابتاً يمكن مشاركته أو تخمينه.

الحد الأقصى الافتراضي: **500 ميغا** لكل ملف (قابل للتعديل في `supabase.sql`).

> **ملاحظة عن الترقية لمنصة تعمل حالياً:** أي محاضرات كانت مرفوعة *قبل* هذا التحديث موجودة في bucket `maqlama` العام القديم وتبقى تعمل (يوجد fallback تلقائي لها في الكود)، لكنها تبقى قابلة للوصول بالرابط المباشر كما كانت. لحمايتها بنفس مستوى المحتوى الجديد بالكامل، أعد رفعها من صفحة الكورس (حذف ثم إضافة من جديد) بعد تنفيذ `supabase.sql` المحدَّث؛ سيُخزَّن الملف الجديد تلقائياً في `maqlama-lessons` المحمي.

## 🛡️ الأمان والصلاحيات

- كل الجداول لديها **RLS** مفعّلة، والصلاحيات كلها مطبَّقة من قاعدة البيانات نفسها — وليست مجرد إخفاء أزرار في الواجهة. لو طالب حاول الوصول لمحاضرة أو اختبار أو ملف بدون تسجيل (حتى برابط مباشر أو عبر أدوات المطوّر)، سيُرفض الطلب من الخادم.
- وظيفة `public.is_admin()` (SECURITY DEFINER) تمنع التصعيد بالامتيازات.
- **الكورسات والمسارات (العناوين والوصف والصور فقط) تظهر لكل الطلاب، وأيضاً لأي زائر غير مسجَّل دخول عبر "الأقسام"،** ليتصفّحوا الكتالوج، لكن محتواها (فيديوهات/ريكوردات/ملفات/اختبارات) لا يظهر ولا يمكن فتحه إلا لمن سجّله الأدمن فعلياً في `enrollments` / `path_enrollments`. الكورس غير المسجَّل به الطالب أو الزائر يظهر بشارة 🔒 ومحاولة فتحه تعرض نافذة "اشترك الآن" بدل أي محتوى.
- **البث المباشر مرتبط بكل كورس على حِدة:** الطالب لا يرى ولا يقدر يفتح إلا بث الكورسات المسجَّل فيها فعلاً، مطبَّق من RLS في القاعدة (`live_streams`) وليس مجرد إخفاء واجهة.
- **الشات أُلغي بالكامل من الواجهة** (لا يظهر في القائمة ولا في أي صفحة). جداول الشات القديمة (`chat_rooms`, `chat_messages`) وبياناتها تبقى محفوظة في القاعدة كما هي دون حذف، لكنها غير مستخدَمة من الواجهة الحالية.
- عدد الطلاب المسجَّلين في أي كورس أو مسار لا يظهر أبداً في واجهة الطالب — هذه البيانات تظهر فقط لصفحة "الطلاب" الخاصة بالأدمن.
- صلاحيات Storage: bucket `maqlama` (صور/شات) القراءة عامة والرفع للمسجَّلين فقط؛ bucket `maqlama-lessons` (محتوى المحاضرات) **خاص بالكامل** — القراءة تتطلب فحص تسجيل حقيقي في القاعدة، والحذف/الرفع للأدمن فقط.
- كلمات المرور مشفّرة من قِبَل Supabase Auth (bcrypt) — لا نخزّنها أبداً.
- من لوحة الأدمن (صفحة **الطلاب** → زر 🔑) يمكن تسجيل أي طالب في كورس/مسار أو إلغاء تسجيله في أي وقت، والتغيير يصل للطالب فوراً (Realtime) دون الحاجة لتحديث الصفحة.

### تحديث مشروع Supabase قائم فعلاً
كل التعديلات في `supabase.sql` مكتوبة بشكل آمن لإعادة التنفيذ (`create or replace`, `drop policy if exists`, `on conflict`, إلخ). إذا كان لديك مشروع Supabase يعمل بالفعل بنسخة سابقة من هذا الملف، يكفي نسخ **كامل** محتوى `supabase.sql` الجديد ولصقه في SQL Editor وتشغيله مرة أخرى — لن يحذف أي بيانات موجودة.

## 🔗 روابط التواصل الاجتماعي (فوتر المنصة)

قسم "تواصل معنا" في فوتر صفحة تسجيل الدخول يعرض أيقونات: فيسبوك، تيليجرام، واتساب، إنستغرام، يوتيوب.

لتعديل الروابط، افتح `script.js` وابحث عن `SOCIAL_LINKS` (بالقرب من بداية الملف)، وضع الرابط الحقيقي لكل منصة بين علامتي الاقتباس:

```js
const SOCIAL_LINKS = {
  facebook:  'https://facebook.com/your-page',
  telegram:  'https://t.me/your-channel',
  whatsapp:  'https://wa.me/9665XXXXXXXX',
  instagram: 'https://instagram.com/your-page',
  youtube:   'https://youtube.com/@your-channel',
};
```

أي منصة تُترك فارغة `''` ستظهر أيقونتها معطّلة (باهتة وغير قابلة للنقر) بدل رابط وهمي، إلى أن تضيف رابطها الحقيقي.

## 🔒 جلسة واحدة لكل طالب (Single Device Session)

حساب أي طالب يمكن استخدامه من **جهاز واحد فقط في نفس الوقت**:

- عند تسجيل الدخول من جهاز ثانٍ، تُنهى الجلسة على الجهاز الأول **تلقائياً** ويظهر عليه فوراً رسالة "تم تسجيل الدخول إلى حسابك من جهاز آخر"، بينما تظهر على الجهاز الثاني رسالة توضّح أن الحساب كان مفتوحاً على جهاز آخر وتم نقل الجلسة إليه.
- المنع مطبَّق بالكامل من **قاعدة البيانات (Backend)**، وليس مجرد إخفاء أزرار في الواجهة:
  - عمود `active_session_id` في `profiles` يحدّد الجهاز النشط الوحيد، ولا يمكن لأي طالب تعديله مباشرة (محمي بـ trigger) — يتغيّر فقط عبر دالة `claim_device_session()` عند الدخول.
  - سياسات RLS لمحتوى المحاضرات/الملفات الخاصة/الاختبارات/الشات/البث المباشر تتحقق من تطابق جلسة الطلب (`session_ok()`) قبل السماح بأي قراءة أو كتابة.
  - Edge Function باسم **`session-guard`** تستدعي `auth.admin.signOut(token, 'others')` من Supabase Auth مباشرة بعد كل دخول، فتُلغي (تُبطل) أي refresh token لجلسات أخرى لنفس الحساب من الخادم فعلياً — لا يعتمد النظام على عنوان IP إطلاقاً.
- الأدمن مستثنى من هذا القيد عمداً (يحتاج غالباً أكثر من جهاز/تبويب لإدارة المنصة).
- عند الضغط على **تسجيل الخروج** تُفرَّغ الجلسة النشطة فوراً ويصبح بإمكان أي جهاز آخر الدخول لنفس الحساب مباشرة.
- إغلاق المتصفح أو انتهاء الجلسة بدون تسجيل خروج **لا يحجز الحساب بشكل دائم**: أي محاولة دخول جديدة (من نفس الجهاز أو من جهاز مختلف) تنجح دائماً وتصبح هي الجلسة النشطة الجديدة تلقائياً.

**خطوة النشر المطلوبة (مرة واحدة):**
1. نفّذ `supabase.sql` المحدَّث كاملاً في SQL Editor (آمن على مشروع قائم فعلاً — لا يحذف بيانات).
2. انشر Edge Function الجديدة عبر Supabase CLI:
   ```bash
   supabase functions deploy session-guard
   ```
   (نفس الطريقة التي تُنشر بها `admin-users` — تستخدم الأسرار التلقائية `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` بدون أي إعداد إضافي.)
3. (اختياري لكن يُنصح به لتشديد الحماية أكثر) من **Authentication → Settings** قلّل مدة صلاحية الـ JWT (Access Token expiry) — كلما قلّت المدة كلما أصبح إبطال الجهاز القديم فورياً بدل انتظار انتهاء صلاحية التوكن الحالي.

> ملاحظة: لو تعذّر نشر `session-guard` لأي سبب، تبقى الحماية الأساسية عاملة (منع الوصول للمحتوى عبر RLS + تسجيل خروج فوري بالـ Realtime بمجرد دخول جهاز آخر) — الفنكشن طبقة تشديد إضافية تُبطل الجلسة القديمة من جذورها في Auth.

## ❓ مشاكل شائعة

| المشكلة | الحل |
|---|---|
| "Supabase غير مفعّل" | عدّل `env.js` وأعد التحميل |
| لا تستطيع تسجيل الدخول لأول مرة | عطّل **Confirm email** في Supabase Auth |
| لا تظهر الرسائل لحظياً | تأكد أن Realtime مفعّل (مفعّل في `supabase.sql`) |
| فشل رفع ملف كبير | غيّر `file_size_limit` في bucket `maqlama` |
| ظهرت رسالة "تم تسجيل الدخول من جهاز آخر" رغم أنك نفس المستخدم | هذا متوقّع لو فتحت نفس الحساب على جهاز/متصفح مختلف — النظام يسمح بجهاز واحد فقط في نفس الوقت لحسابات الطلاب |
